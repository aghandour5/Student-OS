## 2024-03-24 - Pre-computing Sets for Complex Graph Traversals
**Learning:** In React applications with complex data graph traversals like `getPrerequisiteChain` (BFS algorithms), performing O(N) `.includes()` checks on arrays within loops leads to O(N^2) or worse time complexities. This is especially problematic in diamond dependencies.
**Action:** Always pre-compute frequently accessed arrays (like `completedCourses` or localized level trackers) into `Set` structures *before* starting the loop. Converting these checks to O(1) `.has()` lookups prevents massive performance degradation. Avoid changing functional state updaters though (e.g. `setProfile(prev => ...)`).
## 2024-03-24 - React Performance Anti-Pattern: Instantiating Sets for Single Lookups
**Learning:** Instantiating a new `Set` inside a frequently called function (like `getCourseStatus` or `arePrereqsMet`) just to perform a single `.has()` lookup is a performance anti-pattern. While it looks like O(1) conceptually, creating the `Set` incurs O(N) memory allocation and hashing overhead every time the function runs, which is actively worse than a simple array `.includes()` check.
**Action:** Only use Sets when iterating over large datasets or when doing multiple lookups *after* creating the Set once (e.g. outside a `while` loop like in `getPrerequisiteChain`). For Context callbacks, if Sets are needed, they should be pre-computed and memoized using `useMemo` at the component level, not inside the callback itself.
